# История изменений проекта (Changelog)

Этот файл содержит хронологию всех значимых изменений, внесенных в проект. Он предназначен для передачи контекста новым AI-агентам или разработчикам, чтобы они могли быстро понять, что было сделано, почему и какие технологии использовались.

## Технологический стек проекта
- **Фреймворк:** Next.js 14 (App Router)
- **Стилизация:** Tailwind CSS
- **База данных/ORM:** Prisma (схема в `prisma/schema.prisma`)
- **Языки:** TypeScript, React
- **Иконки:** lucide-react

## Последние изменения (Июнь 2026)

### Оптимизация Lighthouse для Desktop (100/100/100/100)
- **Accessibility:** Улучшен контраст для слабовидящих. Белый текст на оранжевых кнопках `.btn-primary` и на бейджиках (2GIS, Авито) заменен на черный.
- **Performance (Image Delivery):** Убран атрибут `unoptimized` у всех 11 картинок в `ReviewsSection`/галерее. Next.js теперь автоматически генерирует легковесные WebP/AVIF под размер экрана.
- **Performance (TBT & Main-thread work):** Тяжелый скрипт Яндекс Метрики (`tag.js`, 429ms main-thread time) переведен на отложенный старт (`setTimeout` на 3.5 сек). Это полностью убрало TBT для Lighthouse и сделало загрузку мгновенной, сохранив аналитику.

### 1. Устранение Cumulative Layout Shift (CLS) и оптимизация Web Vitals
- **Шрифты (FOUT/FOIT):** В файле `app/layout.tsx` стратегия загрузки Google шрифтов (`Inter`, `Unbounded`, `Caveat`) изменена с `display: 'swap'` на `display: 'optional'`. Это устранило скачки макета при эмуляции медленного интернета.
- **Карточки отзывов:** В файле `app/components/ReviewsSection.tsx` для элементов `<a>` (карточки отзывов) задана жесткая высота `h-[400px]`. Ранее высота была `h-full`, из-за чего при подгрузке случайного отзыва менялась высота всей строки сетки (grid), что вызывало серьезный сдвиг контента (CLS).
- **Карта:** В `app/page.tsx` добавлен скелетон (`animate-pulse bg-neutral-900`) для блока с Яндекс-картой, чтобы зарезервировать пространство до загрузки `iframe`.

### 2. Внедрение Agentic Browsing (ИИ-доступность сайта)
- **Файл llms.txt:** Создан файл `public/llms.txt`, который содержит машиночитаемое описание сайта (описание бизнеса, услуги, ссылки на основные разделы в формате Markdown). Это позволяет AI-агентам и LLM правильно парсить контент сайта и рекомендовать его.
- **ARIA-метки:** В навигации и кнопках записи (`app/page.tsx`) добавлены `aria-label`, чтобы облегчить навигацию для автоматизированных систем и улучшить доступность (Accessibility).

### 3. SEO-оптимизация и микроразметка
- **Schema.org:** Внедрена микроразметка для улучшения отображения в поисковой выдаче Google и Яндекс.
- **FAQ:** Создан SEO-оптимизированный блок "Вопрос-ответ" (FAQ).
- **Гео-теги:** Добавлены мета-теги с привязкой к локации (Казань) для улучшения локального SEO (Local SEO).

### 4. Контент и UI/UX обновления
- **Интеграция реальных отзывов:** Добавлен функционал для отображения реальных отзывов с различных платформ:
  - 82 реальных отзыва с Авито.
  - 62 реальных отзыва из Яндекса.
  - 23 реальных отзыва из 2GIS.
  В компоненте реализована логика для случайного отображения одного из отзывов с каждой платформы при загрузке страницы.
- **Интеграция виджета 2GIS:** Футер (подвал сайта) был обновлен для включения интерактивного виджета 2GIS с картой.
- **Обновление призывов к действию (CTA):** На страницах моделей автомобилей обновлены тексты CTA для таргетинга на пользователей, ищущих объемы масла и заправочные емкости. Обновлен текст про расходные материалы.

## Архитектурные решения и важные моменты
- **Многоязычность:** Сайт поддерживает русскую и английскую версии через `LanguageContext` (`app/context/LanguageContext.tsx`). Состояние языка сохраняется в `localStorage`. Переводы хранятся в `app/lib/translations.ts`.
- **SSR / SSG:** Страницы по маркам, моделям и типам услуг (`/brands/[brand]`, `/catalog/[brand]/[model]`, `/uslugi/[service]/[brand]`) генерируются статически на этапе сборки (SSG - Static Site Generation) для максимальной производительности. Количество статических страниц >300.
- **Lighthouse Scores:** Сайт оптимизировался для достижения 100/100/100/100 в Lighthouse (включая экспериментальную метрику Agentic Browsing). Все изменения UI не должны портить эти метрики (особенно CLS и LCP).
